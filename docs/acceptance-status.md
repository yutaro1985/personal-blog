## 次の作業単位

1. **現状棚卸し**: 下記の最小入力を受領し、非公開レポートと保持/廃止候補を作成。
2. **代表記事の変換/照合**: 合成試験とは別に実記事を取り込み、変換差分・画像・状態・日時・SEO を照合。
3. **編集と認証の受入**: 認証作成の許可後、利用者による passkey 登録、IME/画像/preview/公開操作と端末紛失復旧を確認。
4. **URL と公開テーマ**: 実 URL 一覧からルート/個別301を決め、ページ送り/分類/添付/feedを含め検査。
5. **クラウド復旧/運用**: 資源作成の別承認後に検証環境を準備し、raw DB/PITR とメディアの一組を復元。RPO/RTO を実測。
6. **全量リハーサルと本番判断**: gate を満たした後に切替を相談。自動公開しない。

## 最初に必要な最小入力と安全な受け渡し

まず全 DB や WordPress の認証情報は不要。次を最小セットとする。

- 代表記事 3〜5 本を含む **WXR 1.2**。長文、日本語 slug、画像、表/コード/埋め込み等を含める。公開状態の検証用に提供可能な下書きを含める場合は、その存在と取扱いを明示する。
- その記事が参照する **画像・添付の原本**。`uploads/YYYY/MM/...` 等の相対パスを保持したコピー。WXR に画像本体は含まれない。
- 元の公開 URL と、サイトの timezone/パーマリンク設定。可能なら元記事の公開 HTML または照合対象 URL。
- SEO/特殊ブロックに関係するプラグイン名と継続必須の機能一覧。パスワード、API key、移行 token は含めない。

Mac 上の利用者が管理する非公開ディレクトリに置き、**内容をチャットや GitHub に貼らず、ローカルパスだけ**を伝える。例えば、この clone の `.private/source/` を 0700、ファイルを 0600 として保存する。Git ignore は公開防止の補助であり、共有フォルダーや静的配信ディレクトリには置かない。別端末から渡すなら、承認された暗号化ストレージ/ファイル転送を使い、鍵や認証情報をリポジトリに保存しない。

受領後は元ファイルを読み取り専用の基準として保持し、ハッシュを記録。作業用コピーで検査し、非公開タイトル・URL を含む report、取り込み DB、ログも公開しない。現行 WordPress からの export 操作やプラグイン導入をエージェントが行う場合は、別途その操作の許可が必要。

DB 全体と uploads 全量は全量リハーサル/復旧検証の段階で必要になる。まずは上記の限定サンプルで採用適合性を検証し、不要な個人情報や認証情報を収集しない。
