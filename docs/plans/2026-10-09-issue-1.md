## 判断

Cloudflare 公式構成の Astro + EmDash + ローカル D1/R2 を使う。Node/SQLite の別実装や独自 CMS を作るより移行先の実行環境に近く、クラウド資源は不要。公開 URL は棚卸しが済むまで仮の `/posts/{slug}/` と `/pages/{slug}/` とし、301 は推測で作らない。キャッシュは全面 no-store、noindex、localhost に限定。追加プラグイン、暗号鍵、ユーザー認証情報を生成しない。

EmDash 1.2.0 (2026-10-06) を npm と公式 release で確認。公式 templates の参照 SHA は `1930243108073ebb41ff48533678af7635b01c37`。パッケージは exact pin と lockfile で固定する。1.2.0 の管理 UI 言語制限、ドメイン変更、API ページ送りの変更を確認済み。最新という理由だけで採用済みとはしない。

## 実装単位と検証

1. **ローカル CMS 基盤**: mise / npm / Wrangler、Astro SSR、EmDash 標準管理 UI、記事・固定ページ・分類・RSS・SEO、合成 seed。`astro check`、ビルド、localhost HTTP で確認。
2. **棚卸し支援**: WXR を読み取り専用で解析し、投稿状態・URL・画像参照・特殊 HTML/ブロック/ショートコードを非公開 JSON に記録。外部取得とインポートは行わない。公開・下書き・予約・日本語 slug・XML 不正・重複をテストする。
3. **境界の検証**: localhost 以外を拒否し、応答に no-store/noindex を付加。匿名で下書きが出ないこと、404、RSS、管理 UI、robots を HTTP で確認。実認証を伴う編集・プレビューは未検証として記録する。
4. **復旧**: サーバー停止中の `.wrangler` ローカル状態 (D1 と R2) を別ディレクトリへコピーし、ハッシュ照合と復元後の HTTP 表示を検証。D1 本番時点復旧の実証とは区別。
5. **運用文書**: 現状調査表、代表記事受入表、復旧、全量リハーサル、本番切替と切り戻し手順、未確定の判断項目を記録。Issue は完了扱いにしない。

機能テストは先に失敗を確認して実装し、フォーマット・全テスト・型検査・ビルドを実行する。最後に仕様、公開状態、個人情報の混入、文書と実装の一致を自己レビューする。単一のローカル PoC という目的でまとめる。  
開始時点では push/PR/Issue コメント/Project 更新を対象外としていた。  
その後の許可で Issue コメントと Draft PR を公開した。  
現在の PR 更新範囲は冒頭の記載に従う。Project 更新は対象外。
